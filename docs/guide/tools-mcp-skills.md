# Tools、MCP 与 Skills

三者都能扩展 Agent，但承担的职责不同：Tool 是可执行动作，MCP 是外部工具接入协议，
Skill 是指导 Agent 如何完成一类任务的说明和配套资源。

## Tools 目录

Tools 页面支持按来源和状态浏览工具，并执行创建、编辑、测试、启停和审计。

当前创建表单支持的工具形态以界面选项为准，包括：

- HTTP：配置 URL 等调用参数；
- SQL：配置带命名参数的查询模板；
- Python：编写脚本，可先检查脚本或测试运行。

建议创建后先在目录中单独测试，再把工具绑定到 Agent。Python 工具编辑时应同时检查
参数定义和返回结构，避免脚本能运行但 Agent 无法理解结果。

## MCP 服务器

MCP 页面可以：

1. 输入 endpoint 快速测试连通性；
2. 注册 `stdio`、HTTP 等界面支持的 MCP 服务器；
3. 自动发现服务提供的工具；
4. 搜索、测试工具并保存工具绑定；
5. 查看工具 Schema 历史和 Agent 绑定关系；
6. 重新探测并同步工具。

注册 `stdio` 服务时填写命令和参数；注册网络服务时填写 endpoint，必要时填写认证
Header。工具过滤器可限制暴露给平台的工具集合。

## Skills 中心

Skill 可以手写创建，也可以上传 ZIP 包或文件夹。每个 Skill 至少应说明：

- 何时使用；
- 执行步骤；
- 输入、输出和约束；
- 失败处理和示例。

详情抽屉中可以浏览或编辑 Skill 文件。上传新版包后先预览和校验，再发布；有审批
流程的包还可以拒绝或设置权限。

## 如何选择

| 需求 | 选择 |
|---|---|
| 调用本平台直接实现的 HTTP、SQL 或 Python 能力 | Tool |
| 接入另一个系统已经提供的标准化工具服务 | MCP |
| 给 Agent 补充领域流程、规范和使用方法 | Skill |
| 既需要规则又需要执行动作 | Skill + Tool/MCP |
