# 核心概念

平台资源之间的关系如下：

| 概念 | 用途 | 典型配置位置 |
|---|---|---|
| Provider | 模型服务供应商和公共连接参数 | 模型接入 |
| Model | 具体上游模型及其能力、价格和覆盖参数 | 模型接入 |
| Model Slot | 用途稳定的模型插槽，例如聊天、推理或向量化 | 模型接入 |
| Tool | 平台直接管理的可调用能力 | Tools 目录 |
| MCP Server | 通过 MCP 协议提供工具的外部服务 | MCP 服务器 |
| Skill | 写给 Agent 的专业说明、步骤、约束及配套文件 | Skills 中心 |
| Agent | 将模型、工具、Skill、MCP、记忆和编排组合成可运行助手 | Agent 管理 |
| Session | 用户和 Agent 的连续对话上下文 | 交互问答 / Agent 工作台 |
| Memory | 可跨轮次或跨会话使用的长期信息 | 记忆管理 |

## 配置层级

模型通常不是直接写死在 Agent 中，而是先绑定到模型插槽。Agent 再选择插槽或设置覆盖
策略。这样更换底层模型时，不需要逐个修改 Agent。

平台支持业务域和组织上下文。列表、Agent、Skill、记忆等资源可能随当前业务域或
`org_id` 不同而变化。排查“资源找不到”时，应先核对页面顶部或筛选器中的上下文。

## 两个对话入口

- **交互问答**：偏业务问答，支持知识库范围、附件、语音、来源和上下文面板。
- **Agent 工作台**：偏 Agent 调试与正式执行，展示模型调用、工具调用、任务、文件、
  日志、压缩和记忆等运行细节。
