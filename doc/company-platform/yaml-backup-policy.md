# YAML 备份与回退策略

## 结论

目前 YAML 在平台里不是“双路存储”，也不应作为运行时 fallback 主链路。  
它的定位是：

1. 初始化模板与兼容入口  
2. SQLite 迁移前备份输入源  
3. 人工恢复时的参考文件

## 推荐策略

### 1. 初始化模板

```text
启动时按缺省资源创建/覆盖 workspace 下的模型/工具/MCP/Skill/Agent 模板（只读 seed）
```

### 2. SQLite 迁移前备份

```text
启动或迁移入口执行前：
- 备份当前 .yml 文件（带时间戳）
- 记录备份路径到启动日志
- 仅用于可回滚，不参与主运行请求链路
```

### 3. 人工恢复参考

当 SQL 数据出问题或需要回放时：

```text
读取 yaml 作为字段参考 -> 由平台管理工具导入 -> 重新落库
```

## 禁止行为（与用户要求一致）

```text
不使用 YAML 与 SQLite 并行作为同一实体的主存储读写源
不在每次运行时向 YAML 写回平台状态
```
